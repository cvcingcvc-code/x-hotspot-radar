## 🔍 审计发现的潜在风险与修复方案

| 序号 | 风险等级 | 涉及模块与问题定位 | 修复方案与防御机制 |
| :---: | :---: | :--- | :--- |
| **1** | **中危 (Medium)** | **URL Protocol 注入与 XSS 风险**<br>`AccountWizardModal.jsx` 中用户可自定义输入 handle 与头像 URL，若传入恶意伪协议（如 `javascript:`）可能导致链接异常。 | **引入 `sanitizeHandle` 与 `sanitizeSafeUrl`**：对 Handle 严格执行 X 官方字符白名单（仅保留字母、数字与下划线，限长 15 位）；对头像链接强制校验必须为 `https://`、`http://` 或本地安全路径，否则自动降级为安全默认头像。 |
| **2** | **中危 (Medium)** | **客户端缓存污染与白屏崩溃 (DoS)**<br>`accountEngine.js` 中 `loadStoredAccounts` 缺少反序列化 Schema 校验，若 `localStorage` 字段缺失（如 `targetNiche` 为空），会导致 `.map()` 抛出致命 TypeError 导致全站白屏。 | **建立 `sanitizeAccount` 结构性防御清洗函数**：对读取出的每一个账号对象补齐防御性默认值，确保 `targetNiche` 始终为非空字符串数组，杜绝任何属性读取崩溃。 |
| **3** | **低危 (Low)** | **反向标签页劫持风险 (Reverse Tabnabbing)**<br>`Sidebar.jsx` 与 `Header.jsx` 中部分带有 `target="_blank"` 的外部跳转链接缺少 `noopener` 属性。 | **统一样式与属性加固**：所有外跳链接统一补齐 `rel="noopener noreferrer"`，彻底切断新窗口对原窗口的 `window.opener` 引用。 |
| **4** | **低危 (Low)** | **剪贴板异步拒绝未捕获崩溃**<br>`CopywritingStudio.jsx` 中直接调用 `navigator.clipboard.writeText`，在部分未开启 HTTPS 或被沙箱禁用的环境会抛出 `NotAllowedError` 未捕获异常。 | **实现 `safeCopyText` 兼容方案**：采用 `try...catch` 配合隐藏式 `textarea` 剪贴板降级机制（Fallback），保证在任何环境下均能 100% 成功复制且零报错。 |
| **5** | **优化 (Enhance)** | **超长文本撞击与 UI 破坏 (Input Bombing)**<br>输入框（Handle、昵称、赛道标签、文案框）缺少长度限制，粘贴大段文本可能撑破卡片。 | **全量注入 `maxLength` 边界限制**：Handle 限制 40 字符、展示昵称限制 30 字符、推文草稿限制 2000 字符、回复限制 280 字符。 |
